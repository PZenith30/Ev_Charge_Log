2. หน้าบันทึกการชาร์จ
 - มีข้อมูลพื้นฐาน วันที่ เวลาที่ใช้ในการชาร์จ (ชั่วโมง นาที วินาที) AC/DC สถานีชาร์จ
 - ข้อมูลรถ เลขไมล์ก่อนชาร์จ เลขไมล์หลังชาร์จ ระยะทางที่วิ่งได้ SOCก่อนชาร์จ SOCหลังชาร์จ
 - ข้อมูลพลังงาน จำนวนพลังงานที่ชาร์จ (kWh) ราคา/kWh ค่าบริการเพิ่มเติม ค่าใช้จ่ายรวมต่อครั้ง
 - อัตราสิ้นเปลืองเฉลี่ยที่อ่านจากหน้าปัดรถ (เลือกหน่วยได้ km/kWh หรือ km/100kWh และจำหน่วยที่เลือกไว้)
 - แนบรูปภาพได้ เช่น สลิปธนาคาร ภาพแคปหน้าจอจากแอพชาร์จรถ
3. ระบบคำนวณอัตโนมัติ
 - คำนวณระยะทางที่วิ่งได้จากเลขไมล์ก่อนชาร์จและเลขไมล์หลังชาร์จ
 - คำนวณ SOC ก่อนชาร์จและหลังชาร์จ
 - คำนวณค่าใช้จ่ายรวมต่อครั้งจากจำนวนพลังงานที่ชาร์จและราคา/kWh
 - คำนวณ Efficiency จากระยะทางที่วิ่งได้และจำนวนพลังงานที่ชาร์จ(แสดง2 หน่วย km/kWh และ km/100kWh)
 - คำนวณค่าใช้จ่ายสะสม
 - คำนวณ บาท/km

# Tech Stack ที่ใช้จริง
- Next.js 15 (App Router) + React 19
- JavaScript ล้วน (.jsx) ไม่ใช้ TypeScript — ลดโอกาสที่ type error จะทำให้ build บน Vercel พัง
- ไม่มี dependency นอกเหนือจาก next / react / react-dom
- CSS เขียนเองใน app/globals.css ด้วย CSS variables (ไม่ใช้ Tailwind หรือ UI library)
- กราฟทุกตัวเป็น SVG ที่เขียนเอง ไม่มี chart library
- ทุกหน้าเป็น Client Component เพราะข้อมูลอยู่ในเบราว์เซอร์ทั้งหมด

# การเก็บข้อมูล — Supabase (อัปเดต 27 ส.ค. 2569)
- ฐานข้อมูล Postgres บน Supabase · เข้าถึงจากเบราว์เซอร์ด้วย anon key + Project URL
- ตาราง: cars, charge_sessions, costs, reminders, settings (สคริปต์อยู่ที่ supabase/schema.sql)
- ทุกตารางเปิด Row Level Security ผูกกับ auth.uid() ผู้ใช้เห็นเฉพาะข้อมูลของตัวเอง
  anon key เปิดเผยได้เพราะความปลอดภัยอยู่ที่ RLS ไม่ใช่ที่การซ่อน key
- รูปแนบเก็บใน Supabase Storage บัคเก็ต `charge-images` (private)
  path เป็น <user_id>/<uuid>.jpg และ policy ตรวจโฟลเดอร์แรกเทียบกับ auth.uid()
  แสดงผลผ่าน signed URL อายุ 1 ชม. · ย่อเหลือด้านยาวสุด 1600px บีบ JPEG 0.82 ก่อนอัปโหลด
- ชื่อคอลัมน์เป็น snake_case แต่โค้ดแอปใช้ camelCase — แปลงกันที่ lib/mappers.js ที่เดียว
  ทำให้ lib/calc.js และทุกหน้าจอไม่ต้องแก้เลยตอนย้ายมาใช้ Supabase
- ยังใช้ localStorage เฉพาะค่าที่ผูกกับเครื่อง: ธีม (ให้สคริปต์ตั้งธีมอ่านก่อนหน้าเว็ปวาด)
  และสถานะ "ดูรถทุกคัน"
- การเขียนข้อมูลเป็นแบบ optimistic — อัปเดตหน้าจอทันที ถ้าเขียนฐานข้อมูลพลาดจะแจ้งเตือน
  แล้วดึงข้อมูลจริงกลับมาทับ

# การย้ายข้อมูลจากรุ่นเดิม
- ผู้ใช้ที่เคยใช้รุ่น localStorage จะเห็นการ์ดในหน้าบัญชีให้กดย้ายขึ้น Supabase
- ระบบออก uuid ใหม่ให้ทุกแถว ผูก carId กลับให้ถูก อัปโหลดรูปจาก IndexedDB ขึ้น Storage
  แล้วลบข้อมูลเดิมในเครื่องทิ้ง (lib/legacy.js)
- ข้อมูลที่เคยเก็บ duration เป็นนาที ถูกแปลงเป็นวินาทีระหว่างย้าย

# ข้อจำกัดที่ต้องรู้
- ระบบแจ้งเตือนยังเป็นแบบ in-app (เห็นตอนเปิดเว็ป) ไม่ใช่ push notification
- ไฟล์ส่งออก JSON มีเฉพาะข้อมูลตัวเลข/ข้อความ ไม่รวมรูป เพราะรูปอยู่ใน Supabase Storage
- การนำเข้าไฟล์จะ "เพิ่ม" เข้าบัญชีปัจจุบัน ไม่ได้แทนที่ของเดิม (ปลอดภัยกว่า)

# การตัดสินใจที่ตกลงกับผู้ใช้
- เก็บข้อมูลแบบ localStorage + IndexedDB
- กราฟเขียนเป็น SVG เอง ไม่พึ่ง CDN / library
- ลิสต์ยี่ห้อ-รุ่นรถ EV ฝังในตัวแอป (lib/data.js) พร้อมความจุแบตและระยะทางของแต่ละรุ่น
  เลือก "อื่นๆ" เพื่อพิมพ์ยี่ห้อ/รุ่นเองได้
- รายงาน: สรุปรายเดือน/รายปีในเว็ป + ปุ่มพิมพ์เป็น PDF + ส่งออก CSV

# การแก้ไขรอบที่ 2 (27 ส.ค. 2569)
- เวลา: ตัดช่อง "เวลาเริ่มชาร์จ" ออก เหลือ "เวลาที่ใช้ในการชาร์จ" ช่องเดียว กรอกเป็น ชม. : นาที : วินาที
  เก็บในฐานข้อมูลเป็น `durationSec` (วินาที) แทน `duration` (นาที) แบบเดิม
  ข้อมูลเก่าถูกแปลงให้อัตโนมัติตอนเปิดแอปและตอนกู้คืนไฟล์สำรอง (migrateSession ใน lib/storage.js)
  ผลข้างเคียง: การเรียงลำดับรายการที่อยู่วันเดียวกันใช้ลำดับที่บันทึกแทนเวลานาฬิกา
- ระยะทาง: แสดงทศนิยมตามที่กรอกจริง ไม่ปัดเป็นจำนวนเต็ม (fmtDist ใน lib/format.js)
  300 -> "300", 300.5 -> "300.5" ไม่เติม .0 ให้รก และตัดเศษที่เกิดจาก floating point ทิ้ง
  ใช้กับทั้งระยะทางต่อครั้ง ระยะทางสะสม และเลขไมล์
- อัตราสิ้นเปลืองหน้าปัด: เลือกหน่วยได้ระหว่าง km/kWh และ km/100kWh
  เก็บลงฐานข้อมูลเป็น km/kWh เสมอ (`dashEff`) พร้อมจำหน่วยที่กรอก (`dashEffUnit`) ไว้แสดงกลับ
  หน่วยที่เลือกล่าสุดถูกจำไว้ใน settings.dashEffUnit และใช้เป็นค่าตั้งต้นครั้งถัดไป
  เปลี่ยนหน่วยระหว่างกรอก ระบบจะแปลงตัวเลขที่พิมพ์ไว้ให้ด้วย
  กรอกทศนิยมได้ไม่เกิน 2 ตำแหน่งทั้งสองหน่วย (limitDecimals ใน lib/format.js ตัดส่วนเกินขณะพิมพ์)
  เดิมหน่วย km/100kWh ตั้ง step="1" ไว้ ทำให้พิมพ์ทศนิยมแล้วเบราว์เซอร์บล็อกการ submit ทั้งฟอร์ม
- CSV: เพิ่มคอลัมน์ "เวลาที่ใช้ชาร์จ (ชม:นาที:วิ)" และ "หน้าปัด (km/100kWh)" / "หน่วยที่กรอก"

# การกรอกตัวเลข (ปรับทั้งแอป)
- ช่องตัวเลขทุกช่อง (27 ช่อง) ใช้ step="any" + inputMode="decimal"
  เดิมตั้ง step เป็นค่าคงที่ (0.01 / 0.1 / 1 / 100) ซึ่งเบราว์เซอร์ถือว่าค่าที่ไม่ลงตัวกับ step
  เป็นค่าไม่ถูกต้อง แล้ว "บล็อกการกดบันทึกทั้งฟอร์ม" พร้อมข้อความภาษาอังกฤษที่ผู้ใช้งงว่ามาจากไหน
  เช่น พลังงาน 24.567 kWh หรือเลขไมล์ 12345.67 km จะบันทึกไม่ได้
  ตอนนี้กรอกละเอียดเท่าไหร่ก็ได้ทุกช่อง และคีย์บอร์ดมือถือมีปุ่มจุดทศนิยมให้ครบ
- ข้อยกเว้นเดียว: ช่องอัตราสิ้นเปลืองหน้าปัด จำกัด 2 ตำแหน่งตามที่ตกลงไว้
  แต่บังคับด้วย JS (limitDecimals) ไม่ใช่ step เบราว์เซอร์จึงไม่บล็อกการบันทึก
- ช่อง ชม./นาที/วินาที กรอกเกิน 59 ได้ ระบบรวมเป็นวินาทีแล้วปรับหน่วยให้ตอนแสดงผล
  เช่น กรอก 90 นาที -> แสดง "1 ชม. 30 นาที"
- ข้อจำกัดที่ยังคงไว้เพราะเป็นเงื่อนไขจริงของข้อมูล: min="0" ทุกช่อง และ max="100" ของ SOC

# ขั้นตอนตั้งค่า Supabase (ทำครั้งเดียว)
1. สร้างโปรเจกต์ที่ supabase.com
2. SQL Editor > New query > วาง supabase/schema.sql ทั้งไฟล์ > Run
   (สร้างตาราง, RLS policy, บัคเก็ตรูป และ trigger สร้าง settings ให้ผู้ใช้ใหม่)
3. Project Settings > Data API คัดลอก Project URL และ anon public key
4. ใส่เป็น environment variable ชื่อ
   NEXT_PUBLIC_SUPABASE_URL และ NEXT_PUBLIC_SUPABASE_ANON_KEY
   - ในเครื่อง: คัดลอก .env.local.example เป็น .env.local
   - บน Vercel: Project Settings > Environment Variables แล้ว Redeploy
5. Authentication > URL Configuration ตั้ง Site URL เป็น URL ของเว็ปบน Vercel
   เพื่อให้ลิงก์ยืนยันอีเมลและลิงก์ตั้งรหัสใหม่เด้งกลับมาถูกที่

# รอบที่ 7 — ผู้ช่วย AI (Chat Bot ด้วย Gemini)
- ปุ่มแชทลอยมุมขวาล่าง เปิดแผงถามได้จากทุกหน้า (components/ChatWidget.jsx)

โครงสร้าง
- app/api/chat/route.js — Route Handler เรียก Gemini ฝั่ง server
  คีย์ GEMINI_API_KEY ไม่มี NEXT_PUBLIC_ จึงไม่หลุดไปกับโค้ดหน้าเว็ป
  ตรวจ Supabase access token ก่อนเรียกทุกครั้ง กันคนนอกยิงจนโควตาฟรีหมด
  แปลง SSE ของ Gemini เป็นสตรีมข้อความธรรมดา ฝั่งเบราว์เซอร์อ่านด้วย TextDecoderStream
  ไม่ฝังชื่อรุ่นตายตัว — ถามรายชื่อจาก API แล้วเลือกให้เอง (lib/aiModels.js)
  เพราะ Google เปลี่ยน/ปลดชื่อรุ่นเรื่อยๆ และแต่ละบัญชีเห็นไม่เหมือนกัน
  ตั้ง GEMINI_MODEL เมื่ออยากบังคับรุ่นเท่านั้น · ถ้ารุ่นที่ตั้งไว้ 404 จะหาตัวแทนแล้วยิงใหม่ให้
  แยก error เป็น NO_KEY / BAD_KEY / BAD_MODEL / QUOTA / UPSTREAM พร้อมข้อความไทย
- lib/aiPrompt.js — ความรู้เรื่องเว็บ: มีหน้าอะไร ฟิลด์แปลว่าอะไร สูตรคำนวณทั้งหมด
  และกติกาการตอบ (ห้ามแต่งตัวเลข ตอบไทย ไม่ใช้ Markdown)
  ถ้าแก้สูตรใน lib/calc.js ต้องมาแก้ไฟล์นี้ให้ตรงกันด้วย
- lib/aiContext.js — สรุปข้อมูลผู้ใช้จาก summarize/monthlyTotals/dueList ที่มีอยู่แล้ว
  ตัวเลขที่ AI เห็นจึงตรงกับหน้าจอเสมอ ขนาดจริงราว 6.4KB ต่อคำถาม

ความเป็นส่วนตัว
- ส่งค่าสรุป + การชาร์จล่าสุด 25 รายการ ไม่ส่งทะเบียนรถ อีเมล path รูป หรือ id ภายใน

# รอบที่ 9 — สถานีชาร์จ: ใกล้ตำแหน่งจริง + ค้นหาได้
ปัญหาที่แก้: หน้าเดิมเริ่มต้นที่กรุงเทพฯ เสมอ ผู้ใช้ต่างจังหวัดจึงเห็นสถานีที่ไม่เกี่ยวกับตัวเองเลย
และไม่มีทางพิมพ์หาสถานที่ที่ต้องการได้ ต้องเลือกจากเมืองตั้งต้น 7 เมืองเท่านั้น

- ขอตำแหน่งจริงตั้งแต่เปิดหน้า ไม่รอให้กดปุ่มก่อน
  ลำดับ: ตำแหน่งที่เคยใช้ล่าสุด > ขอ GPS จากเบราว์เซอร์ > กรุงเทพฯ (พร้อม toast บอกว่ายังไม่ได้ตำแหน่ง)
  ใช้ ref กันไม่ให้ทำงานซ้ำตอน React StrictMode เรียก effect สองรอบ
- ตำแหน่งที่ได้จาก GPS ติดธง gps:true ไว้ เปิดหน้าครั้งถัดไปจะแสดงค่าเดิมทันที
  แล้วเช็ก GPS ซ้ำเงียบๆ เผื่อผู้ใช้เดินทางไปที่อื่น (ตอนนั้นอนุญาตแล้วจึงไม่มีป๊อปอัพถามซ้ำ)
  อัปเดตเฉพาะเมื่อขยับเกิน ~550 ม. (movedFar) เพราะ GPS คืนค่าแกว่งทุกครั้ง
  ถ้าอัปเดตทุกครั้งจะยิง API ใหม่โดยไม่ได้อะไรเพิ่ม
- ช่องค้นหาสถานที่ — พิมพ์ชื่อห้าง อำเภอ หรือจังหวัด แล้วเลือกจากรายการเพื่อย้ายจุดค้นหา
  หน่วง 500ms ก่อนยิง และต้องพิมพ์อย่างน้อย 2 ตัวอักษร กด Enter เลือกรายการแรกได้
- ช่องกรองรายการ — กรองสถานีที่โหลดมาแล้วด้วยชื่อ ผู้ให้บริการ ที่อยู่ หรือชนิดหัวชาร์จ
  ทุกคำที่พิมพ์ต้องเจอ จึงค้นแบบ "ptt ลาดพร้าว" ได้ ไม่ต้องยิง API ใหม่

app/api/geocode/route.js — พร็อกซีไปที่ Nominatim ของ OpenStreetMap
- ทำเป็น Route Handler เพราะนโยบายของ Nominatim บังคับให้ส่ง User-Agent ที่ระบุตัวแอป
  ซึ่งเบราว์เซอร์ตั้งเองไม่ได้ · แคชที่ CDN 24 ชม. ลดภาระเซิร์ฟเวอร์อาสาสมัครของ OSM · เลี่ยง CORS
- ฟรี ไม่ต้องใช้คีย์ จึงไม่มีตัวแปรใหม่ที่ต้องตั้งใน Vercel
- จำกัดผลลัพธ์ในไทย (countrycodes=th) ภาษาไทย สูงสุด 6 รายการ timeout 8 วินาที

ทางเลือกที่ไม่ได้ใช้
- Google Geocoding — แม่นกว่าแต่ต้องเปิด billing และเพิ่มคีย์อีกตัว
- ให้ผู้ใช้กรอกละติจูด/ลองจิจูดเอง — ไม่มีใครทำจริง
# รอบที่ 10 — ปุ่มตรวจการตั้งค่า AI ในแผงแชท

# รอบที่ 11 — แก้ตำแหน่งค้นหาสถานีไม่ตรงจริง
อาการที่ผู้ใช้เจอ: อยู่บางขุนนนท์ แต่สถานีที่ขึ้นเป็นแถวกำแพงเพชร 2 (ห่างราว 9 กม.)
รายการเรียงตามระยะทางถูกอยู่แล้ว แปลว่า "จุดศูนย์กลางที่ใช้ค้น" ผิดตั้งแต่ต้น มี 2 สาเหตุ

1. ค่าตำแหน่งเก่าใน localStorage บังไม่ให้ขอ GPS ใหม่
   รอบที่ 9 เพิ่มธง gps ไว้ใช้ตัดสินว่าควรรีเฟรชไหม แต่ค่าที่เก็บไว้ก่อนหน้านั้นไม่มีธงนี้
   โค้ดจึงมองว่าเป็นตำแหน่งที่ผู้ใช้ตั้งใจเลือก แล้วใช้ค่าเก่าตลอดไปโดยไม่เคยขอ GPS เลย
   แก้โดยเปลี่ยน key เป็น evlog.lastLocation.v2 และบังคับว่าต้องมีฟิลด์ source
   เป็น 'user' (ผู้ใช้เลือกเมือง/ค้นสถานที่เอง) หรือ 'gps' เท่านั้น ค่าที่ไม่รู้ที่มาถูกทิ้ง
   - source 'user' = เคารพตัวเลือก ไม่ไปขอ GPS ทับ
   - source 'gps'  = วาดค่าเก่าไปก่อนไม่ให้หน้าว่าง แล้วขอใหม่ทุกครั้งที่เปิดหน้า

2. ขอตำแหน่งแบบหยาบ (enableHighAccuracy: false)
   แบบหยาบให้เบราว์เซอร์เดาจาก WiFi หรือ IP ซึ่งในกรุงเทพฯ เพี้ยนได้หลายกิโลเมตร
   เดิมเลือกแบบหยาบเพราะเร็วกว่าและกินแบตน้อยกว่า แต่ความแม่นสำคัญกว่ามากในหน้านี้
   เปลี่ยนเป็น locateBest(): ขอละเอียดก่อน (15 วิ) ถ้าไม่ทันค่อยถอยไปแบบหยาบ (10 วิ)
   ถ้าผู้ใช้ปฏิเสธสิทธิ์ไม่ต้องลองซ้ำ เพราะยังไงก็ไม่ได้
   ตั้ง maximumAge: 0 ด้วย จะได้ไม่ได้ค่าที่แคชไว้ตอนอยู่ที่อื่น

ทำให้ผู้ใช้ตรวจสอบเองได้ แทนที่จะเดา
- หัวข้อรายการแสดงพิกัดจริงที่ใช้ค้น เช่น "รอบ ตำแหน่งปัจจุบัน (±25 ม.) · 13.7620, 100.4720"
- ถ้าเบราว์เซอร์บอกว่าคลาดเคลื่อนเกิน 1 กม. ขึ้นแถบเตือนพร้อมบอกสาเหตุ
  (อยู่ในอาคาร/คอมไม่มี GPS) และทางแก้ (พิมพ์ชื่อย่านในช่องค้นหา)
  เกณฑ์ 1 กม. เพราะในเมืองพลาดขนาดนั้นก็คนละย่านแล้ว

หมายเหตุ: ถ้าตำแหน่งถูกต้องแล้วแต่ยังไม่เห็นสถานีที่รู้ว่ามีอยู่จริง
แปลว่า Open Charge Map ยังไม่มีข้อมูลจุดนั้น ซึ่งเป็นฐานข้อมูลที่อาสาสมัครช่วยกันกรอก
ความครอบคลุมในไทยจึงไม่เท่ากันทุกย่าน — เพิ่มเองได้ที่ openchargemap.org

# รอบที่ 12 — ตัดพื้นหลังรูปรถ ให้เหลือแต่ตัวรถบนสีพื้นของธีม
lib/cutout.js — ทำในเบราว์เซอร์ด้วย canvas ล้วน ไม่เพิ่ม dependency ไม่ส่งรูปออกไปไหน
- หาสีพื้นหลังจากจตุรัส 8x8 ที่สี่มุมภาพ ต้องผ่านสองด่าน
  1) ในมุมเดียวกันสีต้องนิ่ง (spread <= 26) กันมุมที่มีต้นไม้หรือลายพื้น
  2) สี่มุมต้องใกล้เคียงกัน (gap <= 40) แต่ยอมให้ไล่เฉดอ่อนแบบฉากสตูดิโอได้
- ลบด้วย flood fill จากขอบภาพเข้ามา ไม่ใช่ไล่ลบทุกพิกเซลที่สีใกล้เคียง
  เพราะรถสีขาวบนพื้นขาวจะโดนลบทั้งคันถ้าเทียบสีอย่างเดียว
  flood fill ลบเฉพาะส่วนที่ต่อถึงขอบ ช่องกระจกสีเดียวกับพื้นหลังจึงไม่หาย (มีเทสต์ยืนยัน)
- ขอบนุ่ม: พิกเซลที่ติดพื้นหลังไล่ความทึบตามความต่างของสี หนีบขั้นต่ำที่ 60
  ไม่งั้นขอบรถจะเป็นฟันเลื่อย และถ้าปล่อยให้จางถึง 0 ตัวรถจะแหว่ง
- ครอบเฉพาะกรอบตัวรถ เว้นขอบ 3% ไม่ให้ชนขอบกล่อง

ยอมไม่ตัดดีกว่าตัดจนรูปพัง — คืน null แล้วใช้รูปเดิมเมื่อ
- มุมภาพไม่ผ่านด่านข้างบน (รูปถ่ายจริงที่มีถนน/ต้นไม้ส่วนใหญ่ตกตรงนี้)
- ตัดได้น้อยกว่า 8% ของภาพ (แปลว่าพื้นหลังไม่ได้เรียบจริง)
- ตัดเกิน 94% (กินตัวรถไปด้วย)
- canvas ถูก taint เพราะปลายทางไม่ส่ง CORS header (โยน SecurityError ตอน getImageData)
ทั้งสามด่านแรกตรวจให้จบก่อนแตะค่า alpha รูปเดิมจึงไม่ถูกแก้เลยเมื่อไม่ผ่าน

การแสดงผล
- รูปที่ตัดแล้วพื้นหลังโปร่งใส จึงเห็นสีพื้นของกล่องที่ครอบอยู่
  เข้าธีมเองทั้งโหมดสว่าง โหมดมืด และแถบข้างที่มืดตลอดเวลา โดยไม่ต้องเขียนสีแยกสามชุด
- ใช้ object-fit: contain (เดิม cover ซึ่งครอบตัดรถ) เห็นทั้งคัน
- แคชผลไว้ต่อ src เก็บ null ด้วย จะได้ไม่ลองซ้ำกับรูปที่ตัดไม่ได้
  แถบข้างกับแดชบอร์ดแสดงรถคันเดียวกันจึงคำนวณครั้งเดียว
- ย่อภาพให้ด้านยาวไม่เกิน 900px ก่อนประมวลผล กันภาพใหญ่ทำให้หน่วง

ทางเลือกที่ไม่ได้ใช้
- API ตัดพื้นหลังสำเร็จรูป (remove.bg ฯลฯ) — ต้องมีคีย์ มีโควตา และต้องส่งรูปผู้ใช้ออกไปข้างนอก
- mix-blend-mode: multiply — ง่ายกว่ามากแต่ใช้ได้เฉพาะพื้นขาวบนธีมสว่าง พอเป็นธีมมืดจะพัง
- โมเดล ML ในเบราว์เซอร์ — แม่นกว่ามากแต่ต้องโหลดโมเดลหลาย MB ผิดหลักไม่เพิ่ม dependency

# รอบที่ 13 — ไอคอนใหม่สำหรับชื่อ KiloEV
โจทย์: มินิมอล คล้ายของเดิม (สายฟ้าขาวบนเขียว) แต่สื่อถึงชื่อ KiloEV

สิ่งที่ลองแล้วไม่เวิร์ก บันทึกไว้กันคิดซ้ำ
- เอาสายฟ้ามาเป็นแขนของตัว K ตรงๆ ไม่ได้ เพราะสายฟ้าเป็นรูปตัว Z (เส้นบนเฉียงลงซ้าย
  เส้นล่างเฉียงขึ้นขวา) ส่วนแขน K เป็นรูป > (ทั้งสองแขนกางออกทางขวา) ทิศทางสวนกัน
- วางขาตั้งไว้ซ้ายแล้วเอาสายฟ้าเต็มตัวมาต่อ อ่านเป็น "l ⚡" ไม่ใช่ K
- เจาะร่องที่ข้อต่อให้ดูเป็นประกายไฟ ที่ 16px กลายเป็นรอยแหว่งเหมือนรูปเสีย
- แขนสองข้างเหลื่อมกันเพื่อทำรอยหักแบบสายฟ้า ทำให้ K ดูขาดเป็นสองท่อน

แบบที่เลือก: K ปลายแขนตัดแนวตั้ง
- ขาตั้งหนา แขนสองข้างบรรจบที่กึ่งกลาง ปลายแขนตัดแนวตั้งจึงแหลมคม
  ได้อารมณ์พุ่งแบบสายฟ้าโดยไม่ต้องวาดสายฟ้า และเหลือรูปทรงน้อยชิ้นพอจะอ่านออกที่ 16px
- แขนต้องเริ่มที่ x=9.5 ซึ่งอยู่ "ข้างใน" ขา (ขากว้าง 7.5-12.3) ไม่งั้นมุมของ
  สี่เหลี่ยมด้านขนานจะเหลือช่องสามเหลี่ยมตรงรอยต่อ เห็นชัดมากตอนย่อ
- ลำดับจุดในแต่ละรูปต้องวนรอบโดยไม่ตัดกันเอง ไม่งั้น point-in-polygon จะเพี้ยนจนรูปแหว่ง

# รอบที่ 16 — ไอคอนรวม K + L + สายฟ้า และเปลี่ยนคู่สี
โจทย์: ให้ K กับ L+สายฟ้าเป็นรูปเดียวกัน และใช้สีที่เข้ากับแอป

รูปเดียวอ่านได้สามอย่าง
- ขาซ้าย  = ขาของทั้ง K และ L ใช้ร่วมกัน จึงไม่ต้องวาดสองขา
- ฐานล่าง = ทำให้อ่านเป็น L
- สายฟ้า  = จรดขาที่กึ่งกลาง แล้วแตกออกเป็นแขนบนกับแขนล่างของ K
            รอยหักตรงกลาง (จุด 17.4, 12.6) คือจังหวะสายฟ้า และเป็นตัวแยกสองแขนไปในตัว

กุญแจที่ทำให้รวมกันได้: เดิมติดตรงที่สายฟ้าเป็นรูป Z ส่วนแขน K เป็นรูป >
รอบนี้แก้โดยวาดสายฟ้าใหม่ให้หางชี้ลงขวาแทนลงซ้าย จึงกลายเป็นแขนล่างของ K ได้พอดี
(BOLT_RIGHT ใน scratchpad) ส่วนสายฟ้าแบบดั้งเดิมที่หางชี้ลงซ้ายอ่านเป็น "L ⚡" เฉยๆ

คู่สีใหม่: เขียว Electric Green (#22c55e) บนพื้น #111827 ซึ่งเป็นสีแถบข้างของแอป
- เป็นคู่สีที่ผู้ใช้เห็นทุกวันในเว็ปอยู่แล้ว ไอคอนจึงดูเป็นแอปเดียวกัน
- คอนทราสต์ดีกว่าขาวบนเขียวมาก จึงเลิกต้องใช้เขียวเข้มพิเศษใน favicon
  ตอนนี้ favicon กับ PNG ใช้สีชุดเดียวกันแล้ว

ตัวตรวจใหม่: scratchpad/svgcheck.js
เทียบจุดใน path ของ app/icon.svg กับ MARK ใน doc/make-icons.js ให้ตรงกันทุกจุด
เขียนขึ้นเพราะรอบนี้เขียน path ด้วยมือแล้วตกจุดปลายไปหนึ่งจุด ซึ่งตาเปล่าไม่เห็น
เพราะคำสั่ง z จะลากปิดรูปข้ามจุดที่หายไป ได้รูปผิดแบบเงียบๆ ตรวจสีทั้งสองไฟล์ด้วย

เลื่อน VERSION ใน sw.js เป็น v4 พร้อมกันตามปกติ

# รอบที่ 17 — จัดน้ำหนักไอคอนใหม่ และทำการ์ดตัวอย่างตอนแชร์ลิงก์
1) ให้ K กับสายฟ้าเด่น L เป็นตัวเสริม
- ฐานของ L บางลงจาก 4.8 เหลือ 3 หน่วย และสั้นลงเหลือ x=16.2
  บางกว่าขาชัดเจน สายตาจึงไปที่ K กับสายฟ้าก่อน แล้วค่อยเห็น L เป็นฐานรอง
- สายฟ้าหนาขึ้นเล็กน้อย (ยอดขยับขึ้นเป็น y=4.2 ปลายล่างยาวลงถึง y=23.4)
- ไม่ลดความหนาขา เพราะขาเป็นตัวยึดทั้ง K และ L ถ้าบางลงรูปจะเสียน้ำหนักตอนย่อ 16px
- เลื่อน VERSION ใน sw.js เป็น v5

2) การ์ดตัวอย่างตอนแชร์ลิงก์ (Open Graph) — doc/make-og.js สร้าง public/og.png
- ขนาด 1200x630 (อัตราส่วน 1.91:1) ซึ่งเป็นเกณฑ์ที่ LINE กับ Facebook แสดงการ์ดใบใหญ่
- เลือกทำเป็น "รูปนิ่งที่สร้างไว้ล่วงหน้า" ไม่ใช้ ImageResponse ของ Next ที่เรนเดอร์ตอน runtime
  เพราะเครื่องนี้ build ไม่ได้ จึงยืนยันผลลัพธ์ของ ImageResponse ไม่ได้เลย
  ส่วนไฟล์นิ่งเปิดดูด้วยตาได้ก่อน deploy และไม่ต้องพึ่ง edge function
- ในรูปมีแค่โลโก้กับชื่อ ไม่ใส่คำอธิบายภาษาไทย เพราะ LINE แสดง og:title กับ
  og:description เป็นข้อความข้างการ์ดอยู่แล้ว ใส่ซ้ำจะรกเปล่าๆ
  (และการวาดอักษรไทยด้วยรูปหลายเหลี่ยมเองไม่คุ้มแรง)
- ตัวอักษร KiloEV วาดเป็นฟอนต์เรขาคณิตเล็กๆ ในไฟล์นั้นเอง (K i l o E V เท่านั้น)
  เพราะ Node ที่ใช้ได้ในเครื่องนี้อ่านไฟล์ฟอนต์ไม่ได้ และไม่อยากเพิ่ม dependency
  "Kilo" สีอ่อน "EV" สีเขียว เพื่อเน้นว่าเป็นแอปรถไฟฟ้า
- เร่งความเร็วด้วยการเก็บกรอบสี่เหลี่ยมของแต่ละรูปไว้ก่อน แล้วข้ามรูปที่จุดไม่ได้อยู่ในกรอบ
  ไม่งั้น 1200x630 x supersample 3x3 x ทุกรูป จะช้ามาก

metadataBase — จำเป็น ถ้าไม่ตั้ง Next จะออก og:image เป็น path สัมพัทธ์ ซึ่ง LINE อ่านไม่ได้
อ่านจาก NEXT_PUBLIC_SITE_URL ก่อน ถ้าไม่มีค่อยใช้ VERCEL_PROJECT_PRODUCTION_URL ที่ Vercel ตั้งให้เอง
ต่อโดเมนของตัวเองเมื่อไหร่ควรตั้ง NEXT_PUBLIC_SITE_URL ไม่งั้นรูปจะชี้ไปโดเมน .vercel.app

หมายเหตุ: ชื่อบนการ์ดแชร์ใช้ KiloEV แล้ว แต่ชื่อในเว็ป (แท็บ/หน้าจอโฮม) ยังเป็น EV Charge Log
เพราะยังไม่ได้สั่งให้เปลี่ยน และการเปลี่ยนชื่อ PWA ต้องถอนแล้วติดตั้งใหม่ถึงจะมีผล

# รอบที่ 18 — ให้เห็น "สายฟ้า" จริงๆ ไม่ใช่แค่แขนของ K
รอบที่ 17 ลดความหนาฐาน L แล้วแต่ยังไม่ตรงโจทย์ กลับมาดูใหม่พบว่าปัญหาไม่ได้อยู่ที่ L
แต่อยู่ที่ตัวสายฟ้าเอง: ปลายทั้งสองข้างตัดตรงเป็นเส้นตั้ง สมองจึงอ่านเป็น
"แขนของตัวอักษร" ไม่ใช่สายฟ้า ต่อให้ทำ L เล็กแค่ไหนก็ยังไม่เห็นสายฟ้าอยู่ดี

แก้ที่ต้นเหตุ
- ปลายสายฟ้าทั้งสองข้างทำให้แหลมเป็นจุดเดียว แทนการตัดตรง
  แค่นี้ก็อ่านเป็นสายฟ้าทันที เพราะปลายแหลมคือลักษณะเด่นของสายฟ้า
- รอยหักกลางเจาะลึกเข้ามาถึง x=14.6 (เดิม 17.4) สองแฉกจึงแยกกันชัด
- ขยายสายฟ้าให้ยาวขึ้นทั้งสองด้าน ยอดถึง y=3.3 ปลายล่างถึง y=25.9
- รูปสายฟ้าเหลือ 5 จุด: จรดขาเป็นก้อนเดียว แล้วแยกเป็นสองแฉก
  ก้อนที่จรดขาสูง 10 หน่วย จึงยึดกับขาแน่น ไม่ขาดตอนย่อ 16px
- ไม่ลดความหนาขา (คงไว้ 4.8) เพราะขายึดทั้ง K และ L ถ้าบางลงรูปเสียน้ำหนัก
  ลองแบบขา 4.4 แล้วอยู่ใน doc/icon-options.png (T2) ดูโหวงกว่า
- ฐาน L บางและสั้นกว่าเดิมอีก (สูง 2.8 ยาวถึง x=14.6)
- ขยับทั้งรูปให้กรอบอยู่กลางกริดพอดี เดิมเบี้ยวไปขวาบนราว 1 หน่วย

เลิกก๊อปพิกัดไว้สองที่
doc/make-og.js เคยก๊อป MARK ไปวางซ้ำ ซึ่งจะหลุดกันทันทีที่แก้รูป
เปลี่ยนเป็น require เอาจาก doc/make-icons.js แทน และห่อส่วนเขียนไฟล์ด้วย
require.main === module ไม่งั้นแค่ require ก็เขียนไอคอนทับ

เลื่อน VERSION ใน sw.js เป็น v6

# รอบที่ 19 — build พังเพราะคอมเมนต์ในไฟล์ SVG (แก้การวินิจฉัยผิดของรอบที่ 14)
Vercel ขึ้น: Image import "...app/icon.svg?__next_metadata__" is not a valid image file

สาเหตุ: Next อ่านขนาดของ app/icon.svg ด้วยไลบรารี image-size
ซึ่งตรวจว่าเป็น SVG จริงไหมโดยอ่านแค่ 1000 ไบต์แรกของไฟล์แล้วหาแท็ก <svg
รอบที่ 13 เอาคอมเมนต์อธิบายไปวางไว้ "ก่อน" แท็ก และเขียนเป็นภาษาไทย
ซึ่ง UTF-8 กินไบต์ละ 3 ตัวอักษร คอมเมนต์จึงยาว 1149 ไบต์ ดันแท็ก <svg เลยเส้น 1000 ไปพอดี
image-size เลยสรุปว่าไฟล์นี้ไม่ใช่รูป และ build ล้ม

ผลกระทบที่ไม่รู้ตัว: build ล้มตั้งแต่ commit 3b2b82f (ไอคอน KiloEV ตัวแรก)
งานทุกอย่างหลังจากนั้นจึงไม่เคยขึ้นเว็ปเลย 6 commit ได้แก่ ไอคอนทุกเวอร์ชัน
กับการ์ดตัวอย่างตอนแชร์ลิงก์

การวินิจฉัยผิดของรอบที่ 14: ตอนผู้ใช้บอกว่า "ไอคอนยังไม่เปลี่ยน" สรุปว่าเป็นเพราะ
service worker แคชของเก่าไว้ ที่จริงคือ build ไม่ผ่านจึงไม่มีอะไรขึ้นไปตั้งแต่แรก
(เรื่องเลื่อน VERSION ยังเป็นสิ่งที่ต้องทำอยู่ แต่ไม่ใช่สาเหตุของอาการครั้งนั้น)
บทเรียน: ก่อนสรุปว่าเป็นเรื่องแคช ต้องยืนยันก่อนว่า deploy สำเร็จจริง

- ย้ายคอมเมนต์เข้าไปไว้ "ข้างใน" แท็ก svg ไฟล์จึงเริ่มด้วย <svg ที่ไบต์ 0

# รอบที่ 20 — เปลี่ยนไอคอนมาใช้โลโก้จริงจาก doc/Gemini_Generated_Image_.jpg
ผู้ใช้ส่งไฟล์โลโก้มาให้ใช้แทนรูปเรขาคณิตที่ทำกันมาหลายรอบ
โลโก้เป็นตัว K ลายมือในวงกลม มีสายฟ้าเฉียงผ่ากลาง ไล่เฉดเขียวมิ้นต์ไปน้ำเงิน

ปัญหาแรกคือไฟล์เป็น JPEG ซึ่งเครื่องนี้อ่านไม่ได้ (ไม่มี Node จริง ไม่มีไลบรารีรูป)

- แปลง JPEG เป็น PNG ด้วย System.Drawing ของ .NET ผ่าน PowerShell
  เพราะเขียนตัวถอด JPEG เอง (huffman + DCT + upsampling) ไม่คุ้มแรงเลย
- ที่เหลือทำใน Node ทั้งหมด เพราะ PNG ถอดเองได้ง่าย แค่ inflate แล้วย้อน row filter
  ตามสูตรในสเปก ราว 60 บรรทัด (doc/make-icons-from-logo.js)

# รอบที่ 21 — เปลี่ยนชื่อเป็น KiloEV ทั้งระบบ และใช้โลโก้ชุดใหม่
ผู้ใช้ส่งภาพแบรนด์มาแผ่นเดียว แบ่งสองช่อง: ช่อง A ไอคอนแอป · ช่อง B ชื่อแบรนด์พร้อมสโลแกน

doc/make-brand.js สกัดทั้งสองช่องจากภาพเดียว
- แบ่งซ้าย/ขวาที่กึ่งกลาง แล้วเริ่มหาเนื้อภาพจาก y=150 ลงมา เพื่อข้ามตัวอักษร A กับ B ที่กำกับไว้
- ค่า tolerance ของสองช่องต่างกันโดยตั้งใจ
  ช่อง A ใช้ 60 (แน่น) ไม่งั้นเงาจางใต้ไอคอนจะถูกนับเป็นเนื้อภาพ กรอบจะเบี้ยว
  ช่อง B ใช้ 70 ซึ่งยังจับตัวอักษรสโลแกนสีเทาอ่อนได้ (ห่างจากพื้นราว 165)
  แต่ไม่ไปจับพื้นที่ไล่เฉดจางๆ — ค่า 28 ที่ลองตอนแรกจับทั้งครึ่งขวาของภาพเลย
- ไอคอนต้องตัดขอบเข้ามาอีก 3.5% เพราะขอบที่ anti-alias กับพื้นสว่างในภาพต้นฉบับ
  ติดมาเป็นเส้นขอบสว่างรอบไอคอน เห็นชัดมากตอนย่อ และเงายังตกไปทางขวาล่างด้วย
- มุมไอคอนใช้รัศมี 0.25 ซึ่งกว้างกว่าของต้นฉบับเล็กน้อย จะได้กินเข้าไปในเนื้อ
  ไม่เหลือมุมสว่างค้าง
- ชื่อแบรนด์ทำพื้นโปร่งใสตามความสว่าง ไม่ใช้ flood fill เหมือนงานก่อน
  เพราะตัวอักษรมีช่องปิดข้างใน (o, e) ที่ flood fill จากขอบเข้าไม่ถึง

การ์ดแชร์เปลี่ยนเป็นพื้นสว่าง (#f7f9fc) เพราะคำว่า "Kilo" เป็นสีกรมท่าเข้ม วางบนพื้นเข้มจะจมหาย
และใช้ public/icon-512.png เป็นภาพไอคอนบนการ์ด เพราะไฟล์นั้นมนมุมและโปร่งใสนอกกรอบอยู่แล้ว
ตรงกับไอคอนที่ส่งขึ้นจริงเป๊ะ (ตอนแรกใช้ brand-icon.png ซึ่งเป็นจตุรัสเต็ม เลยเห็นเป็นกล่องเหลี่ยม)

# รอบที่ 22 — โลโก้ชุดใหม่ + วาง Wordmark + ระบบสองภาษา

## โลโก้ชุดใหม่ (doc/Fav_Icon.jpg และ doc/Wordmark.jpg)
doc/make-brand.js สกัดจากสองไฟล์ ได้ไอคอนสี่ขนาดกับชื่อแบรนด์สี่แบบ

ชื่อแบรนด์ต้องมีสี่แบบเพราะสองมิติคูณกัน
  มี/ไม่มีสโลแกน  ×  สำหรับพื้นสว่าง/พื้นเข้ม
รุ่นพื้นเข้มจำเป็นเพราะคำว่า "Kilo" เป็นกรมท่าเข้ม วางบนแถบข้างสีเข้มจะจมหายไป

จุดที่ต้องแก้ระหว่างทาง บันทึกไว้กันพลาดซ้ำ
- แยกชื่อออกจากสโลแกนด้วย "แถบข้อความ" ไม่ใช่การหาช่องว่างที่กว้างที่สุด
  เพราะไฟล์ต้นฉบับมีเงาจางใต้โลโก้ ช่องว่างที่กว้างที่สุดจึงเป็นช่องระหว่าง
  สโลแกนกับเงา ไม่ใช่ระหว่างชื่อกับสโลแกน ผลคือได้ไฟล์ "ไม่มีสโลแกน" ที่ยังมีสโลแกนติดมา
- ทำรุ่นพื้นเข้มต้องแยกด้วย "ค่าความสด" (ช่องสีที่แรงที่สุด) ไม่ใช่ความสว่างรวม
  เพราะน้ำเงินสดของ EV มีความสว่างรวมต่ำพอๆ กับกรมท่า (103 กับ 33) ใช้ความสว่าง
  แล้ว EV จะซีดตามไปด้วย ส่วนค่าความสดต่างกันชัด: กรมท่า 64 · EV น้ำเงิน 240 · EV เขียว 210
- ไอคอนต้องตัดขอบเข้ามา 5% ทิ้งเส้นขอบสว่างที่เกิดจากการ anti-alias กับพื้นในต้นฉบับ
  และเงาที่ตกไปทางขวาล่าง

## วางชื่อแบรนด์ตามที่ตกลง
- components/Wordmark.jsx ใช้ที่เดียวได้ทุกที่
- แถบข้าง (มืดเสมอ) ส่ง fixed="dark" ไปตรงๆ ไม่ต้องวาดสองรูป
- หน้าล็อกอิน = ชื่อ + สโลแกน · แดชบอร์ด = ชื่ออย่างเดียว
- สลับตามธีมด้วย CSS ไม่ใช่ JavaScript วาดทั้งสองรูปแล้วซ่อนตัวที่ไม่ใช้
  เพราะธีมถูกตั้งที่ <html data-theme> ตั้งแต่ก่อนหน้าเว็ปวาด ถ้ามาเลือกใน React
  จะเห็นรูปผิดสีวาบหนึ่งตอนโหลด (ปัญหาเดียวกับจอขาววาบที่เคยแก้ไปในธีม)

## ระบบสองภาษา ไทย (ค่าเริ่มต้น) / อังกฤษ
lib/i18n.js ออกแบบให้ "ข้อความไทยเป็นคีย์" ไม่ตั้งคีย์แยกแบบ nav.history
- ภาษาไทยเป็นค่าเริ่มต้น พอใช้ไทยเป็นคีย์ โหมดไทยจึงไม่ต้องเปิดพจนานุกรมเลย
- ข้อความที่ยังไม่แปลตกกลับเป็นไทยเอง ไม่ใช่โชว์คีย์ดิบให้ผู้ใช้เห็น
- ข้อมูลคงที่อย่าง NAV / COST_CATS / PERIOD_PRESETS ไม่ต้องแก้โครงสร้าง แค่ห่อ t() ตอนแสดง

แปลที่คอมโพเนนต์กลางทีเดียว ครอบข้อความจาก lib/ ที่เรียก hook ไม่ได้
  Toasts · ConfirmDialog · EmptyState · Field · Stat · Trend · Modal · CollapsibleCard
  ข้อความ error ที่ throw มาจาก lib/supabase.js, lib/storage.js ฯลฯ จึงถูกแปลโดยไม่ต้องแตะไฟล์เหล่านั้น

ห่อ t() ที่เหลือด้วย codemod (สคริปต์อยู่ใน scratchpad) จับสามแบบ
  ค่าแอตทริบิวต์ที่เป็นสตริง · ข้อความระหว่างแท็กในบรรทัดเดียว · ข้อความหลังแท็กปิดตัวเอง
รวม 353 จุด ใน 20 ไฟล์ · ครบ 301 ข้อความไม่ซ้ำ มีคำแปลครบทุกตัว

ภาษาเก็บใน localStorage ไม่เก็บลง Supabase โดยตั้งใจ
  ตาราง settings เป็นคอลัมน์ตายตัว เพิ่มคอลัมน์ต้องรัน SQL ก่อน
  ถ้าผู้ใช้ยังไม่รัน การบันทึกการตั้งค่า "ทั้งหมด" จะพัง ไม่ใช่แค่เรื่องภาษา
  จึงยอมให้เป็นรายเครื่องเหมือนธีมที่มิเรอร์ไว้ในเครื่อง

วันที่กับหน่วยเวลาเปลี่ยนตามภาษาด้วย
  th-TH ให้ปี พ.ศ. · en-GB ให้ปี ค.ศ. เรียงวัน-เดือน-ปี
  lib/format.js อ่านภาษาจากตัวแปรระดับโมดูลใน i18n.js เพราะไม่ใช่คอมโพเนนต์จึงใช้ hook ไม่ได้
  การเปลี่ยนตัวแปรนั้นไม่สั่งให้ React วาดใหม่ แต่ store เปลี่ยน state พร้อมกันอยู่แล้ว

บทเรียนเรื่องเครื่องมือ: เขียนสคริปต์ที่มี regex ผ่าน shell ไม่ได้
  backslash ถูกกินไปหนึ่งชั้น \s กลายเป็น s ทำให้ codemod รอบแรกจับแอตทริบิวต์ไม่ได้เลย
  ต้องเขียนไฟล์ด้วยเครื่องมือที่ไม่แปลงเนื้อหา
