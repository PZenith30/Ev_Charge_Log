2. หน้าบันทึกการชาร์จ
 - มีข้อมูลพื้นฐาน วันที่ เวลาที่ใช้ในการชาร์จ (ชั่วโมง นาที วินาที) AC/DC สถานีชาร์จ
 - ข้อมูลรถ เลขไมล์ก่อนชาร์จ เลขไมล์หลังชาร์จ ระยะทางที่วิ่งได้ SOCก่อนชาร์จ SOCหลังชาร์จ
 - ข้อมูลพลังงาน จำนวนพลังงานที่ชาร์จ (kWh) ราคา/kWh ค่าบริการเพิ่มเติม ค่าใช้จ่ายรวมต่อครั้ง
 - อัตราสิ้นเปลืองเฉลี่ยที่อ่านจากหน้าปัดรถ (เลือกหน่วยได้ km/kWh หรือ km/100kWh และจำหน่วยที่เลือกไว้)
 - แนบรูปภาพได้ เช่น สลิปธนาคาร ภาพแคปหน้าจอจากแอพชาร์จรถ
3. ระบบคำนวณอัตโนมัติ
 - คำนวณระยะทางที่วิ่งได้จากเลขไมล์ก่อนชาร์จและเลขไมล์หลังชาร์จ
 - คำนวณ SOC ก่อนชาร์จและหลังชาร์จ
 - คำนวณค่าใช้จ่ายรวมต่อครั้งจากจำนวนพลังงานที่ชาร์จและราคา/kWh
 - คำนวณ Efficiency จากระยะทางที่วิ่งได้และจำนวนพลังงานที่ชาร์จ(แสดง2 หน่วย km/kWh และ km/100kWh)
 - คำนวณค่าใช้จ่ายสะสม
 - คำนวณ บาท/km

# Tech Stack ที่ใช้จริง
- Next.js 15 (App Router) + React 19
- JavaScript ล้วน (.jsx) ไม่ใช้ TypeScript — ลดโอกาสที่ type error จะทำให้ build บน Vercel พัง
- ไม่มี dependency นอกเหนือจาก next / react / react-dom
- CSS เขียนเองใน app/globals.css ด้วย CSS variables (ไม่ใช้ Tailwind หรือ UI library)
- กราฟทุกตัวเป็น SVG ที่เขียนเอง ไม่มี chart library
- ทุกหน้าเป็น Client Component เพราะข้อมูลอยู่ในเบราว์เซอร์ทั้งหมด

# การเก็บข้อมูล — Supabase (อัปเดต 27 ส.ค. 2569)
- ฐานข้อมูล Postgres บน Supabase · เข้าถึงจากเบราว์เซอร์ด้วย anon key + Project URL
- ตาราง: cars, charge_sessions, costs, reminders, settings (สคริปต์อยู่ที่ supabase/schema.sql)
- ทุกตารางเปิด Row Level Security ผูกกับ auth.uid() ผู้ใช้เห็นเฉพาะข้อมูลของตัวเอง
  anon key เปิดเผยได้เพราะความปลอดภัยอยู่ที่ RLS ไม่ใช่ที่การซ่อน key
- รูปแนบเก็บใน Supabase Storage บัคเก็ต `charge-images` (private)
  path เป็น <user_id>/<uuid>.jpg และ policy ตรวจโฟลเดอร์แรกเทียบกับ auth.uid()
  แสดงผลผ่าน signed URL อายุ 1 ชม. · ย่อเหลือด้านยาวสุด 1600px บีบ JPEG 0.82 ก่อนอัปโหลด
- ชื่อคอลัมน์เป็น snake_case แต่โค้ดแอปใช้ camelCase — แปลงกันที่ lib/mappers.js ที่เดียว
  ทำให้ lib/calc.js และทุกหน้าจอไม่ต้องแก้เลยตอนย้ายมาใช้ Supabase
- ยังใช้ localStorage เฉพาะค่าที่ผูกกับเครื่อง: ธีม (ให้สคริปต์ตั้งธีมอ่านก่อนหน้าเว็ปวาด)
  และสถานะ "ดูรถทุกคัน"
- การเขียนข้อมูลเป็นแบบ optimistic — อัปเดตหน้าจอทันที ถ้าเขียนฐานข้อมูลพลาดจะแจ้งเตือน
  แล้วดึงข้อมูลจริงกลับมาทับ

# การย้ายข้อมูลจากรุ่นเดิม
- ผู้ใช้ที่เคยใช้รุ่น localStorage จะเห็นการ์ดในหน้าบัญชีให้กดย้ายขึ้น Supabase
- ระบบออก uuid ใหม่ให้ทุกแถว ผูก carId กลับให้ถูก อัปโหลดรูปจาก IndexedDB ขึ้น Storage
  แล้วลบข้อมูลเดิมในเครื่องทิ้ง (lib/legacy.js)
- ข้อมูลที่เคยเก็บ duration เป็นนาที ถูกแปลงเป็นวินาทีระหว่างย้าย

# ข้อจำกัดที่ต้องรู้
- ระบบแจ้งเตือนยังเป็นแบบ in-app (เห็นตอนเปิดเว็ป) ไม่ใช่ push notification
- ไฟล์ส่งออก JSON มีเฉพาะข้อมูลตัวเลข/ข้อความ ไม่รวมรูป เพราะรูปอยู่ใน Supabase Storage
- การนำเข้าไฟล์จะ "เพิ่ม" เข้าบัญชีปัจจุบัน ไม่ได้แทนที่ของเดิม (ปลอดภัยกว่า)

# การตัดสินใจที่ตกลงกับผู้ใช้
- เก็บข้อมูลแบบ localStorage + IndexedDB
- กราฟเขียนเป็น SVG เอง ไม่พึ่ง CDN / library
- ลิสต์ยี่ห้อ-รุ่นรถ EV ฝังในตัวแอป (lib/data.js) พร้อมความจุแบตและระยะทางของแต่ละรุ่น
  เลือก "อื่นๆ" เพื่อพิมพ์ยี่ห้อ/รุ่นเองได้
- รายงาน: สรุปรายเดือน/รายปีในเว็ป + ปุ่มพิมพ์เป็น PDF + ส่งออก CSV

# การแก้ไขรอบที่ 2 (27 ส.ค. 2569)
- เวลา: ตัดช่อง "เวลาเริ่มชาร์จ" ออก เหลือ "เวลาที่ใช้ในการชาร์จ" ช่องเดียว กรอกเป็น ชม. : นาที : วินาที
  เก็บในฐานข้อมูลเป็น `durationSec` (วินาที) แทน `duration` (นาที) แบบเดิม
  ข้อมูลเก่าถูกแปลงให้อัตโนมัติตอนเปิดแอปและตอนกู้คืนไฟล์สำรอง (migrateSession ใน lib/storage.js)
  ผลข้างเคียง: การเรียงลำดับรายการที่อยู่วันเดียวกันใช้ลำดับที่บันทึกแทนเวลานาฬิกา
- ระยะทาง: แสดงทศนิยมตามที่กรอกจริง ไม่ปัดเป็นจำนวนเต็ม (fmtDist ใน lib/format.js)
  300 -> "300", 300.5 -> "300.5" ไม่เติม .0 ให้รก และตัดเศษที่เกิดจาก floating point ทิ้ง
  ใช้กับทั้งระยะทางต่อครั้ง ระยะทางสะสม และเลขไมล์
- อัตราสิ้นเปลืองหน้าปัด: เลือกหน่วยได้ระหว่าง km/kWh และ km/100kWh
  เก็บลงฐานข้อมูลเป็น km/kWh เสมอ (`dashEff`) พร้อมจำหน่วยที่กรอก (`dashEffUnit`) ไว้แสดงกลับ
  หน่วยที่เลือกล่าสุดถูกจำไว้ใน settings.dashEffUnit และใช้เป็นค่าตั้งต้นครั้งถัดไป
  เปลี่ยนหน่วยระหว่างกรอก ระบบจะแปลงตัวเลขที่พิมพ์ไว้ให้ด้วย
  กรอกทศนิยมได้ไม่เกิน 2 ตำแหน่งทั้งสองหน่วย (limitDecimals ใน lib/format.js ตัดส่วนเกินขณะพิมพ์)
  เดิมหน่วย km/100kWh ตั้ง step="1" ไว้ ทำให้พิมพ์ทศนิยมแล้วเบราว์เซอร์บล็อกการ submit ทั้งฟอร์ม
- CSV: เพิ่มคอลัมน์ "เวลาที่ใช้ชาร์จ (ชม:นาที:วิ)" และ "หน้าปัด (km/100kWh)" / "หน่วยที่กรอก"

# การกรอกตัวเลข (ปรับทั้งแอป)
- ช่องตัวเลขทุกช่อง (27 ช่อง) ใช้ step="any" + inputMode="decimal"
  เดิมตั้ง step เป็นค่าคงที่ (0.01 / 0.1 / 1 / 100) ซึ่งเบราว์เซอร์ถือว่าค่าที่ไม่ลงตัวกับ step
  เป็นค่าไม่ถูกต้อง แล้ว "บล็อกการกดบันทึกทั้งฟอร์ม" พร้อมข้อความภาษาอังกฤษที่ผู้ใช้งงว่ามาจากไหน
  เช่น พลังงาน 24.567 kWh หรือเลขไมล์ 12345.67 km จะบันทึกไม่ได้
  ตอนนี้กรอกละเอียดเท่าไหร่ก็ได้ทุกช่อง และคีย์บอร์ดมือถือมีปุ่มจุดทศนิยมให้ครบ
- ข้อยกเว้นเดียว: ช่องอัตราสิ้นเปลืองหน้าปัด จำกัด 2 ตำแหน่งตามที่ตกลงไว้
  แต่บังคับด้วย JS (limitDecimals) ไม่ใช่ step เบราว์เซอร์จึงไม่บล็อกการบันทึก
- ช่อง ชม./นาที/วินาที กรอกเกิน 59 ได้ ระบบรวมเป็นวินาทีแล้วปรับหน่วยให้ตอนแสดงผล
  เช่น กรอก 90 นาที -> แสดง "1 ชม. 30 นาที"
- ข้อจำกัดที่ยังคงไว้เพราะเป็นเงื่อนไขจริงของข้อมูล: min="0" ทุกช่อง และ max="100" ของ SOC

# ขั้นตอนตั้งค่า Supabase (ทำครั้งเดียว)
1. สร้างโปรเจกต์ที่ supabase.com
2. SQL Editor > New query > วาง supabase/schema.sql ทั้งไฟล์ > Run
   (สร้างตาราง, RLS policy, บัคเก็ตรูป และ trigger สร้าง settings ให้ผู้ใช้ใหม่)
3. Project Settings > Data API คัดลอก Project URL และ anon public key
4. ใส่เป็น environment variable ชื่อ
   NEXT_PUBLIC_SUPABASE_URL และ NEXT_PUBLIC_SUPABASE_ANON_KEY
   - ในเครื่อง: คัดลอก .env.local.example เป็น .env.local
   - บน Vercel: Project Settings > Environment Variables แล้ว Redeploy
5. Authentication > URL Configuration ตั้ง Site URL เป็น URL ของเว็ปบน Vercel
   เพื่อให้ลิงก์ยืนยันอีเมลและลิงก์ตั้งรหัสใหม่เด้งกลับมาถูกที่

  ไม่ฝังชื่อรุ่นตายตัว — ถามรายชื่อจาก API แล้วเลือกให้เอง (lib/aiModels.js)

  ตั้ง GEMINI_MODEL เมื่ออยากบังคับรุ่นเท่านั้น · ถ้ารุ่นที่ตั้งไว้ 404 จะหาตัวแทนแล้วยิงใหม่ให้

- lib/aiContext.js — สรุปข้อมูลผู้ใช้จาก summarize/monthlyTotals/dueList ที่มีอยู่แล้ว
  ตัวเลขที่ AI เห็นจึงตรงกับหน้าจอเสมอ ขนาดจริงราว 6.4KB ต่อคำถาม

- ส่งค่าสรุป + การชาร์จล่าสุด 25 รายการ ไม่ส่งทะเบียนรถ อีเมล path รูป หรือ id ภายใน

- app/manifest.js — Next.js เสิร์ฟเป็น /manifest.webmanifest และใส่ link ใน head ให้เอง
  display standalone · theme_color ตรงกับธีม · shortcut ไปหน้าบันทึก/ประวัติ/สถานี
  short_name ตั้งไว้ 9 ตัวอักษร เพราะ Android ตัดชื่อที่ยาวเกิน 12 ตัวบนหน้าจอโฮม
- ไอคอน PNG 192/512/maskable/apple-touch สร้างด้วยสคริปต์เขียน PNG encoder เอง
  ใช้ zlib ที่ติดมากับ Node ไม่เพิ่ม dependency และไม่ต้องพึ่งเครื่องมือแต่งรูป
  ตัว maskable ทำพื้นเต็มขอบและย่อสายฟ้าให้อยู่ในเขตปลอดภัย OS จะได้ตัดขอบโดยโลโก้ไม่โดน
- public/sw.js — service worker
  ไม่แตะคำขอที่ไม่ใช่ GET, ไม่แตะ /api/*, ไม่แตะโดเมนภายนอก (Supabase/Google/OCM)
  เพราะแคชพวกนี้จะทำให้เห็นข้อมูลเก่าหรือรูปที่ signed URL หมดอายุ
  หน้าเว็ปใช้ network-first จึงเห็นของใหม่ทันทีหลัง deploy ไม่ค้างรุ่นเก่า
  ไฟล์ static ของ Next ใช้ cache-first ได้เพราะชื่อไฟล์มี hash อยู่แล้ว
- public/offline.html — หน้าสำรองเมื่อเน็ตหลุด กลับเข้าแอปเองเมื่อออนไลน์
- components/PWA.jsx — ลงทะเบียน SW, ปุ่มติดตั้ง (beforeinstallprompt),
  แจ้งเมื่อมีเวอร์ชันใหม่พร้อมปุ่มโหลดทันที และบอกวิธีติดตั้งบน iOS ซึ่งไม่มี event นี้
- ข้อจำกัด: ออฟไลน์เปิดแอปได้แต่ดูข้อมูลไม่ได้ เพราะข้อมูลอยู่บน Supabase

# ยังไม่ได้ทำจากสเปกใหม่ (รอบถัดไป)
- ข้อ 4  Add Charge modal แบ่ง 4 ส่วน (Charging / Battery / Cost / Driving)
         พร้อมฟิลด์ใหม่ ส่วนลด และวิธีการชำระเงิน — ต้องเพิ่มคอลัมน์ใน Supabase
- ข้อ 5  หน้า Statistics
- ข้อ 6  หน้า Cost Analysis รวมกราฟเทียบ EV vs รถน้ำมัน/LPG (ต้องตั้งค่าราคาน้ำมันก่อน)
- ข้อ 7  หน้า Energy Usage แยกตามในเมือง/ทางไกล/AC/DC/ช่วงเวลา
- ข้อ 8  หน้า Vehicle เต็มรูปแบบ (ตอนนี้อยู่รวมในหน้าบัญชี)
- ข้อ 9  ทำแล้วบางส่วน (ดูรอบที่ 6) — ยังเหลือ: เก็บสถานีเป็นตารางในฐานข้อมูลของเราเอง
         พร้อมสถิติจำนวนครั้งที่ใช้/ค่าใช้จ่ายรวมต่อสถานี และแผนที่ในตัว
- ข้อ 13 Reports เพิ่มรายวัน/Custom และส่งออก Excel (ตอนนี้มีรายเดือน/รายปี + PDF + CSV)
- ข้อ 14 หน้า Settings แยกออกมา (ตอนนี้อยู่ในหน้าบัญชี)

# สิ่งที่ยังไม่ได้ทำ / ต่อยอดได้
- ยังไม่มี push notification (ต้องมี service worker + Web Push)
- (ทำแล้วในรอบที่ 8) PWA ติดตั้งลงหน้าจอมือถือได้
- ยังไม่มีการนำเข้าข้อมูลจาก CSV (มีแต่ส่งออก)
- ยังไม่มี realtime sync ระหว่างแท็บ/เครื่อง (Supabase Realtime ทำได้ ถ้าต้องการ)
- ยังไม่มีการแชร์ข้อมูลรถร่วมกันหลายบัญชี
